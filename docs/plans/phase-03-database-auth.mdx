## Mục tiêu

Dùng database hiện có làm nguồn chuẩn và cập nhật NestJS cho meeting nhanh, meeting theo lịch, chọn session, guest approval, member lâu dài, quản lý owner/moderator và mute micro.

## Tiến độ

- [x] Meeting API xác thực bằng application JWT và ánh xạ `sub` về `users.user_id`.
- [x] Phân biệt meeting nhanh một session với meeting dùng lại/session theo lịch.
- [x] Dùng `meeting_sessions.livekit_room_name` và gắn `attendances` đúng `session_id`.
- [x] Guest request, pending list, approve/deny và trạng thái request được giới hạn theo session.
- [x] Guest được duyệt chỉ có quyền session đó; owner/moderator có thể mời user thành member lâu dài.
- [x] Giới hạn ba lần bị từ chối trong 30 phút; trả `retryAt` cho client.
- [x] Member đã được mời có thể lên lịch/kết thúc session; meeting lặp mở rộng RRULE trong tập hỗ trợ.
- [x] Mute/remove kiểm tra thứ bậc owner/moderator; mute chỉ tác động kết nối hiện tại.
- [x] DTO và UUID route validation.
- [ ] Xác minh nullable/default/foreign key/leave_reason trên Supabase development và kiểm thử DB thật.
- [ ] Tích hợp frontend dashboard, chọn session, waiting room và controls.
- [ ] Tự kết thúc session theo lịch và cleanup attendance qua LiveKit webhook.

## Quyết định và giới hạn

- Không sửa schema hoặc áp dụng migration cũ. Backend không còn phụ thuộc `meetings.livekit_room_name`, `meetings.status`, `max_participants` hay `allow_self_unmute`.
- Mute không được duy trì qua reconnect theo quyết định mới nhất.
- Khi tắt waiting room, request đang chờ vẫn giữ trạng thái pending; cài đặt mới áp dụng cho lượt join sau.
- RRULE hiện hỗ trợ FREQ daily/weekly/monthly/yearly với các trường phổ biến; các field/tổ hợp khác bị từ chối. Cần so với format mà client/DB thực tế sử dụng.
- Chưa chạy automated tests hoặc kết nối Supabase/LiveKit. Backend/frontend typecheck và frontend build đã qua.
