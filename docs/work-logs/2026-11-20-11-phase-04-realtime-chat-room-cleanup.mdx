## Scope and final decisions

Date: 2026-11-20 (Asia/Saigon). Phase 04 remains In Progress. No commit/push or live DB/schema writes in this change.

- Club-channel chat now uses Socket.IO instead of polling every three seconds.
- Meeting chat keeps its existing Socket.IO implementation; acknowledgement no longer waits for every recipient's access check.
- Final user clarification: a meeting still opens in the separate full-page meeting view. Do not embed it into the club workspace shell. Only remove the duplicate overview with the welcome headline and create/join forms, plus its internal “Tổng quan” back button.
- Creation remains in workspace. Public-home navigation in the full-page header remains; it does not reopen the removed meeting overview. Opening the generic meeting shortcut without a room code takes the user to workspace.
- Shared `/api/meetings` APIs remain: workspace already calls these for creation, scheduling, admission and LiveKit credentials. They are not duplicate APIs that can safely be deleted with the overview UI.

## Channel transport

Socket.IO namespace: `/workspace-chat`, WebSocket transport through the existing `/socket.io` proxy.

- Handshake: `{ token, clubId, channelId }`. JWT signature/expiry, account, complete profile and current channel access are checked. IDs are validated; the client cannot set the sender or subscribe to an arbitrary room after connection.
- `channel:send`: `{ client_message_id, content }`. Acknowledgement is `{ ok: true, data: { item } }` or `{ ok: false, code, message }`. Existing persistence and duplicate-send UUID checks remain in `WorkspaceChannels.send`.
- `channel:message`: saved message, pushed only to currently authorized recipients in the matching club/channel. `mine` is computed per recipient; retry keys are omitted for other senders.
- `channel:revoked`: access ended; disconnect and clear the local channel messages. Idle access is rechecked every 30 seconds, JWT expiry has a timer, and delivery checks access before pushing content.
- Socket text sends are limited per user (30 attempts/minute). Failed sends retain the draft and retry UUID. Pending rows are not marked delivered until the server confirms them.
- Images/files still upload over the authenticated HTTP multipart endpoint. Both HTTP and socket persistence paths publish a saved-message event so attachments appear immediately for connected recipients.
- History and older pages remain authenticated HTTP reads. They run on connection/reconnection or explicit pagination, not on a three-second timer. Reconnection walks backwards until previously known history is reached, including gaps longer than 50 messages. Incoming live messages and history responses merge by message ID.
- Socket disconnection disables sending and retains the draft. The client reconnects automatically; the existing retry button can recreate a failed connection.

## Meeting transport

Existing namespace `/chat` still authenticates the JWT, meeting/session admission and LiveKit presence. Existing cursor catch-up and retry outbox remain. A saved send returns acknowledgement before broadcasting finishes; recipients still pass current-access checks before content delivery. A slow recipient no longer delays the sender's saved acknowledgement.

## Deployment and follow-up

Restart an already-running production backend to register the new namespace, then reload frontend clients. Vite/tunnel already forwards WebSocket upgrades for `/socket.io`; no proxy route or database migration is required. Servers were not started or restarted by this task.

The saved-message bus and Socket.IO adapter are currently process-local. Run one backend instance for delivery; multiple backend instances would need shared pub/sub and the appropriate Socket.IO adapter. Direct SQL/Supabase-dashboard writes do not publish application events. Durable history allows recovery after disconnection, but live delivery is not guaranteed while a client is disconnected.
