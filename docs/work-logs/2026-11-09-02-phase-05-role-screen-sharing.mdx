## Objective and completed code

Everyone can raise a hand. Only the actual host gets screen-share and screen-share-audio sources on initial join token; moderators and participants request permission. MeetingsService returns role in join response and enables canUpdateOwnMetadata for hand/request attributes. New authenticated screen-share/decision endpoint validates actual creator plus admitted host membership, ongoing session, active attendance matching session and exact LiveKit identity, admitted/nonremoved target and pending request. Server updates LiveKit permission, not database schema.

FE ScreenShareButton requests/cancels through participant attributes when not permitted. Host sees realtime requester names and approve/deny controls through ScreenShareRequests. Approval grants sources to the current connection; user clicks again to open browser picker. Denial displays status and allows retry. Arbitrary client attributes never grant publication permission. MeetingRoom uses the server role to show host UI, while BE independently authorizes every decision.

Existing MeetingMediaLayout displays camera grid without sharing, and a large object-fit contain screen stage with camera sidebar while sharing; mobile collapses to screen plus camera strip. Multiple approved presenters use existing presenter selector. Added request styles to match both themes.

## Decisions and limits

No persistent approval store. Grants last for the current LiveKit participant connection; a fresh join requires approval again. No automatic screen capture after approval because browser requires a user gesture. Owner alone approves; moderator also requests. No revoke action added in this scope. Existing SDK room disappearance race during moderation can require retry.
