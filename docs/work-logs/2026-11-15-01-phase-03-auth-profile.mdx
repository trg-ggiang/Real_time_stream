## Decisions and limitations

- Kept the existing NestJS bcrypt/JWT authentication rather than switching auth providers, consistent with the current app integration.
- Used `student_profiles.user_id` upsert on conflict; the schema extract did not include constraints, so verify that `user_id` is unique/primary key in the development database before exercising save.
- Did not change schema or add migrations. The provided schema extract did not establish current foreign keys, unique constraints, duplicate profile rows, or RLS policies.
- Email verification, password reset, and edits to `users.display_name`/`avatar_url` are not implemented in this code change.
- `docs/docs.json` has pre-existing merge conflict markers, so it was not modified; this new work-log page cannot be registered in navigation until that file's conflict is resolved.
