## 1. Mục tiêu và cách đọc

Tài liệu bám source hiện tại của Module 1: NestJS cấp token, React hiển thị phòng, LiveKit Cloud xử lý kết nối/media. Dành cho người hiểu khái niệm nhưng chưa chắc cú pháp và cách triển khai. Không cần đọc node_modules để theo tài liệu này.

Mỗi hàm được giải thích bằng: ai gọi và lúc nào → đầu vào/đầu ra → biến và tham số → thứ tự xử lý → câu chốt trách nhiệm. Với module, config hoặc component thư viện, các trường cấu hình/props cũng được giải thích riêng. Những đoạn code rút gọn chỉ bỏ phần không liên quan, không phải đề xuất thay source.

Phạm vi không có database/auth, phòng động, chat, screen share hoặc recording. Có dependency trong package.json không có nghĩa tính năng đó đã được triển khai.

Đường dẫn trong tài liệu tính từ root repository. Chỉnh source trong src; không chỉnh dist hoặc .js.map.

### 1.1. Ba chương trình và hai loại request

| Phần | Nơi chạy | Trách nhiệm |
| --- | --- | --- |
| NestJS | Node.js trên máy chạy backend | Đọc cấu hình, nhận HTTP và ký token |
| React + LiveKit client | Browser của mỗi người tham gia | Xin token, mở thiết bị, kết nối và render media |
| LiveKit Cloud | Hạ tầng LiveKit | Chấp nhận token hợp lệ và phân phối media |
| Vite/cloudflared | Máy chạy môi trường thử | Phục vụ frontend, proxy API và tạo đường HTTPS |

```text
Browser -- POST /api/livekit/token --> NestJS
Browser <-- token + URL + room + identity -- NestJS
Browser <========= media/signaling =========> LiveKit Cloud
```

Backend không chuyển tiếp camera/mic. Frontend không ký token. Tunnel không thay thế LiveKit Cloud. Các tab riêng là các phiên frontend riêng, không chia sẻ một hook instance.

### 1.2. Trình tự đọc

1. Lệnh npm và backend bootstrap: package.json → main.ts → app.module.ts → environment.ts → configure-app.ts.
2. Mở trang: index.html → main.tsx → MeetingPage.tsx.
3. Nhấn Join: use-meeting-session.ts → token-api.ts → controller → service.
4. Nhận token: hook cập nhật state → MeetingRoom.tsx → SDK và RoomContent.
5. Leave: callback → xóa state → unmount → SDK cleanup.
6. Vận hành, compiler, CSS, tests và giới hạn.

### 1.3. Cú pháp được sử dụng xuyên suốt

| Cú pháp | Nghĩa và điều dễ nhầm |
| --- | --- |
| `import { X } from '...'` | Lấy named export; package name lấy từ thư viện, `./...` lấy từ file tương đối |
| `import type { X }` | Chỉ dùng kiểu lúc kiểm tra TypeScript; không cần import runtime đó |
| `export` / `export default` | Cho file khác sử dụng bằng named/default import |
| `const x = ...` | Không gán lại biến x; object mà x trỏ đến vẫn có thể thay đổi |
| `x: T` | TypeScript khai báo kiểu; không phải chuyển kiểu runtime |
| `T \| null` | Union: giá trị có thể thuộc kiểu T hoặc null |
| `x?: T` | Thuộc tính/tham số có thể bị bỏ qua; thường phải xét undefined |
| `x?.method()` | Chỉ gọi nếu x không null/undefined; không nuốt lỗi bên trong method |
| `a ?? b` | Dùng b khi a null/undefined; vẫn giữ 0, false và chuỗi rỗng |
| `a \|\| b` | Dùng b khi a falsy, bao gồm 0/false/chuỗi rỗng |
| `...object` | Chép thuộc tính vào object mới; thuộc tính khai báo sau ghi đè thuộc tính trước |
| `() => expression` | Hàm trả expression; `() => ({...})` trả object literal |
| `async` / `await` | Hàm trả Promise; await chờ công việc trong luồng hàm, không khóa toàn browser |
| `try/catch/finally` | Thử xử lý / bắt lỗi / dọn dẹp khi rời khối, kể cả khi lỗi |
| `throw new Error(...)` | Dừng luồng bình thường bằng exception; nơi gọi có thể catch |
| `value as T` / `value!` | Cam kết với TypeScript; không tự validate dữ liệu runtime |
| `<T>` | Generic type; ví dụ `get<number>` không tự biến chuỗi thành số |
| `void promise` | Bỏ giá trị expression/Promise; không tự catch lỗi Promise |
| `<Component prop={value} />` | JSX: component và props; dấu ngoặc nhọn chứa expression JavaScript |
| `flag` trong JSX | Prop boolean true, tương đương `flag={true}` |
| `@Decorator(...)` | Metadata để framework hiểu class/method; không phải hàm handler tự gọi mỗi request |

## 2. Root package.json — Từ lệnh terminal tới chương trình

File không chứa hàm nghiệp vụ. Nó định nghĩa workspaces, phiên bản runtime yêu cầu và scripts.

| Trường | Giá trị / vai trò | Hệ quả |
| --- | --- | --- |
| name | real-time-stream | Tên package root, không phải tên LiveKit room |
| version | 0.0.0 | Phiên bản package nội bộ |
| private | true | Ngăn npm publish nhầm package này; không tự bảo vệ web/API |

| engines.node | >=22.12.0 | Phiên bản Node dự án yêu cầu; mức cưỡng chế tùy cấu hình npm |
| engines.npm | >=10 | Phiên bản npm yêu cầu |
| scripts | Object ánh xạ tên sang lệnh | `npm run tên` chạy lệnh tương ứng |

| Script root | Lệnh làm gì |
| --- | --- |
| dev:backend | Chạy script dev của workspace backend, Nest watch |
| dev:frontend | Chạy script dev của workspace frontend, Vite dev |

**Chốt file:** package.json là bảng lệnh và cấu trúc package, không tự chạy cuộc họp. Nó quyết định chương trình nào được gọi khi thành viên nhập một lệnh npm.

## 3. backend/src/main.ts — Khởi động server

### 3.1. Imports

| Import | Vai trò |
| --- | --- |
| reflect-metadata | Nạp hỗ trợ metadata runtime mà Nest/decorators sử dụng; import chỉ để thực thi, không lấy biến |
| Logger | Tiện ích log của Nest |
| ConfigService | Dependency đọc cấu hình |
| NestFactory | Factory tạo ứng dụng Nest |
| AppModule | Module gốc mô tả cấu trúc ứng dụng |
| configureApp | Hàm nội bộ áp dụng thiết lập HTTP chung |

### 3.2. Hàm bootstrap()

**Ai gọi:** đoạn cuối main.ts gọi một lần khi tiến trình backend bắt đầu. **Đầu vào:** không có tham số. **Đầu ra:** Promise hoàn tất sau khi listen thành công; lỗi sẽ reject.

```ts
const app = await NestFactory.create(AppModule);
const config = app.get(ConfigService);
configureApp(app);
await app.listen(
  config.getOrThrow<number>('PORT'),
  config.getOrThrow<string>('HOST'),
);
```

| Biến/tham số | Nguồn và kiểu sử dụng | Vai trò |
| --- | --- | --- |
| app | Kết quả await NestFactory.create | Instance ứng dụng: container DI, HTTP server và API cấu hình |
| AppModule | Class import từ app.module.ts | Điểm bắt đầu để Nest dựng module/dependency graph |
| config | app.get(ConfigService) | Instance đọc config đã được validate, không phải object env thô |
| PORT | ConfigService, mặc định 3000 | Cổng HTTP server; generic number không tự parse |
| HOST | ConfigService, mặc định 127.0.0.1 | Interface bind; loopback chỉ trực tiếp truy cập từ cùng máy |
| 'Bootstrap' | Context của Logger | Nhãn phân loại log, không ảnh hưởng route |

NestFactory.create khởi tạo các thành phần AppModule khai báo; ConfigModule sẽ xử lý môi trường trong quá trình init. Sau đó configureApp thêm /api và CORS. listen mở cổng; chỉ sau await listen mới log ready. Server tiếp tục sống để nhận request, không kết thúc theo việc bootstrap đã resolve.

**Chốt hàm bootstrap():** Tạo ứng dụng, áp dụng cấu hình và bắt đầu nghe HTTP. Hàm đóng vai trò điều phối khởi động; nó không cấp token hoặc xử lý media.

### 3.3. Callback bắt lỗi khởi động

```ts
void bootstrap().catch(() => {
  Logger.error('API startup failed. ...', undefined, 'Bootstrap');
  process.exitCode = 1;
});
```

| Thành phần | Vai trò |
| --- | --- |
| callback không có tham số | Cố ý không lấy/in error gốc để tránh lộ credentials |
| undefined ở Logger.error | Không cung cấp stack trace ở vị trí tham số này |
| process.exitCode = 1 | Đánh dấu tiến trình lỗi; không phải ép thoát ngay như process.exit(1) |
| void | Không sử dụng Promise sau catch; catch mới xử lý reject |

**Chốt callback catch:** Báo lỗi bootstrap bằng thông tin chung và exit code thất bại. Đây là hàng cuối xử lý lỗi khởi động, không xử lý lỗi request sau khi server đã chạy.

## 4. backend/src/app.module.ts — Từng trường cấu hình Nest

```ts
@Module({
  imports: [
    ConfigModule.forRoot({ isGlobal: true, validate: validateEnvironment }),
    ThrottlerModule.forRoot([{ ttl: 60_000, limit: 10 }]),
    LivekitModule,
  ],
  controllers: [HealthController],
})
export class AppModule {}
```

### 4.1. @Module, imports và controllers

| Tên | Là gì? | Vai trò cụ thể / nếu hiểu sai |
| --- | --- | --- |
| Module | Decorator từ Nest | Gắn metadata cho class; class rỗng vẫn có ý nghĩa nhờ metadata |
| imports | Mảng module ứng dụng sử dụng | Khác câu lệnh import của JavaScript: JavaScript import tên vào file, Nest imports tổ chức DI/module |
| controllers | Mảng controller đăng ký trực tiếp | HealthController được Nest tạo và đăng ký route |
| LivekitModule | Module tính năng | Đưa controller token và service ký token vào ứng dụng |
| AppModule | Class module gốc | NestFactory nhận class này để dựng ứng dụng; không phải instance tự tạo bằng new |

### 4.2. ConfigModule.forRoot — isGlobal thực sự làm gì?

| Trường | Giá trị hiện tại | Vai trò và hệ quả |
| --- | --- | --- |
| isGlobal | true | Cho phép ConfigService của module cấu hình được inject từ module khác mà không phải import ConfigModule ở từng module đó |
| validate | validateEnvironment | Truyền tham chiếu hàm kiểm tra/chuẩn hóa; ConfigModule gọi hàm với dữ liệu môi trường khi khởi tạo |

Nếu bỏ isGlobal hoặc đặt false, module tính năng cần khai báo import phù hợp để sử dụng ConfigService. Nó không làm biến env thành biến JavaScript toàn cục trong browser, không chia sẻ config qua mạng và không tạo database state.

`validate: validateEnvironment` không có dấu ngoặc gọi hàm. Framework quyết định lúc gọi và cung cấp đối số. Viết validateEnvironment() ngay tại đây là gọi sai thời điểm/đầu vào.

Không cấu hình envFilePath riêng: ConfigModule sử dụng hành vi nạp .env mặc định. Workspace backend/script tunnel chạy backend với working directory backend để file env đúng được tìm thấy. Không cần đưa secret vào source.

**Chốt lời gọi ConfigModule.forRoot():** Đăng ký nguồn cấu hình, chạy validation khi bootstrap và cung cấp ConfigService trên phạm vi module toàn ứng dụng. Đây là cơ sở để main/configureApp/LivekitService đọc cùng cấu hình đã chuẩn hóa.

### 4.3. ThrottlerModule.forRoot — ttl và limit thực sự làm gì?

| Trường | Giá trị | Đơn vị / vai trò |
| --- | --- | --- |
| Mảng options | Một object | Thư viện cho phép nhiều cấu hình limiter; dự án chỉ có một cấu hình mặc định |
| ttl | 60_000 | Millisecond: vòng đời/cửa sổ dữ liệu đếm request là 60 giây |
| limit | 10 | Số request cho phép của tracker trong cấu hình đó trước khi bị chặn |
| blockDuration | Không khai báo | Bản thư viện hiện cài mặc định dùng ttl khi không ghi đè; không phải biến riêng trong source dự án |
| storage | Không cung cấp custom | Bộ đếm mặc định trong memory của một tiến trình; restart mất bộ đếm, nhiều replica không chia sẻ |

ThrottlerGuard mới áp dụng cấu hình cho endpoint có guard. Không có global guard trong AppModule, nên health không bị áp dụng limiter này theo cấu hình hiện tại.

Tracker mặc định dựa trên request IP. Key còn liên quan endpoint/cấu hình limiter; không phải danh tính tài khoản vì chưa có auth. Qua Vite proxy loopback, nhiều người có thể được tính chung IP. Không thể kết luận limit=10 là tối đa 10 người trong phòng: nó giới hạn request token, không phải số participant đang kết nối.

**Chốt lời gọi ThrottlerModule.forRoot():** Chuẩn bị chính sách hạn chế tần suất xin token mà guard sẽ sử dụng. Nó giảm request lặp, không thay thế authentication hoặc giới hạn sức chứa phòng.

**Chốt file AppModule:** Lắp ráp các module và controller của backend. Module không xử lý request bằng một hàm riêng; metadata của nó quyết định các dependency và chính sách được chuẩn bị khi Nest bootstrap.

## 5. backend/src/config/environment.ts — Toàn bộ đầu vào và quy tắc

### 5.1. Hàm validateEnvironment(env)

**Ai gọi:** ConfigModule khi khởi tạo. **Đầu vào:** object cấu hình thô. **Đầu ra:** object đã chuẩn hóa; cấu hình sai sẽ throw và khiến bootstrap thất bại.

| Biến cục bộ | Cách tạo | Vai trò |
| --- | --- | --- |
| env | `Record<string, unknown>` | Dữ liệu chưa tin cậy về kiểu; không in toàn object vì có thể chứa secret |
| port | Number(env.PORT ?? 3000) | Cổng đã chuyển sang number để validate và listen |
| frontendUrl | String(env.FRONTEND_URL ?? mặc định) | Origin dùng cho CORS; không phải LiveKit URL |
| origin | new URL(frontendUrl) | Object URL để đọc protocol và origin, kiểm tra chuỗi cấu hình |
| livekitUrl | String(env.LIVEKIT_URL ?? '').trim() | URL signaling LiveKit đã bỏ whitespace; trống vẫn được ở bootstrap |
| ttl | Number(env.LIVEKIT_TOKEN_TTL_SECONDS ?? 300) | Thời hạn token, đơn vị giây; khác ttl throttler đơn vị ms |
| room | String(env.LIVEKIT_ROOM_NAME ?? 'media-test-room').trim() | Tên phòng cố định mà token service sẽ đọc |

| Input | Mặc định / quy tắc | Lý do và ảnh hưởng |
| --- | --- | --- |
| PORT | 3000, số nguyên 1–65535 | Tránh listen trên cấu hình vô nghĩa; 0 không được app runtime chấp nhận qua env này |
| HOST | 127.0.0.1 | Trả về dạng chuỗi; code hiện không validate hostname/interface sâu |
| FRONTEND_URL | http://localhost:5173 | Chỉ http/https origin thuần; không path, query, trailing slash |
| LIVEKIT_URL | Chuỗi rỗng | Nếu có phải là URL parse được và protocol wss:; chưa xác nhận domain thuộc project đúng |
| LIVEKIT_ROOM_NAME | media-test-room | Regex cho chữ/số/_/- và độ dài 1–64 |
| LIVEKIT_TOKEN_TTL_SECONDS | 300 | Chỉ số nguyên 60–600 giây; giới hạn cửa sổ sử dụng token ban đầu |
| NODE_ENV | Giữ nguyên từ env | Chặn đúng trường hợp production cùng POC_ENABLED='true'; không tự đặt mặc định trong hàm |
| POC_ENABLED | false nếu không đúng chuỗi 'true' | Chuyển thành boolean; 'TRUE' hoặc '1' không được coi là bật |
| LIVEKIT_API_KEY/SECRET | Giữ qua ...env | Service kiểm tra khi xin token; validation không log và không tự gọi Cloud |
| Các env khác | Giữ qua ...env | Có biến không đồng nghĩa module đang sử dụng biến đó |

Thứ tự: parse/check port → parse/check frontend origin → parse/check LiveKit URL → parse/check token TTL → parse/check room → kiểm tra production/PoC → trả object.

`new URL(...)` có thể tự throw khi URL không parse được. Kiểm tra `origin.origin !== frontendUrl` cũng loại các phần bổ sung vào origin. `Number('')` là 0, không phải mặc định: ?? chỉ fallback khi null/undefined. Với PORT/TTL rỗng, validation sẽ fail thay vì lặng lẽ dùng default.

```ts
return {
  ...env,
  PORT: port,
  HOST: String(env.HOST ?? '127.0.0.1'),
  FRONTEND_URL: frontendUrl,
  LIVEKIT_URL: livekitUrl,
  LIVEKIT_ROOM_NAME: room,
  LIVEKIT_TOKEN_TTL_SECONDS: ttl,
  POC_ENABLED: env.POC_ENABLED === 'true',
};
```

Các key PORT/... phía sau ghi đè key cũ trong ...env. Đây là nơi chuẩn hóa runtime, không phải generic `get<number>` ở chỗ đọc config.

**Chốt hàm validateEnvironment():** Biến cấu hình thô thành cấu hình backend có quy tắc và kiểu phù hợp; sai thì dừng sớm. Nó không chứng minh credentials được LiveKit chấp nhận và không bắt buộc đủ LiveKit secret để health API chạy.

### 5.2. Ba thời gian tuyệt đối không được nhầm

| Vị trí | Giá trị | Đơn vị | Giới hạn cái gì? |
| --- | --- | --- | --- |
| ThrottlerModule.ttl | 60_000 | ms | Dữ liệu/cửa sổ đếm request rate limit |
| LIVEKIT_TOKEN_TTL_SECONDS | 300 mặc định | giây | Thời hạn JWT dùng cho kết nối ban đầu; không phải timer buộc kết thúc cuộc gọi |
| Hook setTimeout | 15_000 | ms | Thời gian chờ request HTTP xin token |

## 6. backend/src/configure-app.ts — Từng tham số HTTP

### Hàm configureApp(app)

**Ai gọi:** bootstrap và backend test. **Input:** INestApplication. **Output:** void; thay đổi cấu hình trên instance app được truyền vào.

| Biến/trường | Giá trị / nguồn | Vai trò |
| --- | --- | --- |
| app | Tham số Nest app | Đối tượng nhận cấu hình; không tạo app thứ hai |
| config | app.get(ConfigService) | Lấy FRONTEND_URL đã kiểm tra |
| global prefix | 'api' | Thêm /api trước route controller; không cần lặp prefix trong controller |
| cors.origin | FRONTEND_URL | Origin browser được phép đọc response khi khác origin |
| cors.methods | ['GET', 'POST'] | Các HTTP methods được khai báo cho CORS; không phải cách khai báo route |
| shutdown hooks | enableShutdownHooks() | Cho Nest tham gia lifecycle shutdown khi nhận tín hiệu phù hợp; không thay cleanup SDK browser |

Ở cấu hình proxy cùng origin, browser gọi API qua địa chỉ trang, không gọi trực tiếp backend:3000. Server-to-server proxy không bị browser CORS chặn như cross-origin fetch. Vì vậy tunnel không cần đổi FRONTEND_URL theo mỗi hostname ngẫu nhiên trong luồng hiện tại.

**Chốt hàm configureApp():** Áp dụng prefix, CORS và shutdown hooks nhất quán. Đây là cấu hình HTTP dùng chung, không cấp quyền vào phòng.

### 11.5. Hàm join()

**Ai gọi:** onClick Join hoặc tests. **Input:** không có. **Output:** `Promise<void>`; success được thể hiện bằng state, không trả credentials trực tiếp cho nút.

| Biến/expression | Nguồn | Vai trò |
| --- | --- | --- |
| pending.current hoặc joined.current | Refs | Guard đầu hàm chống Join đồng thời hoặc khi đang giữ phiên |
| window.isSecureContext | Browser | Kiểm tra môi trường bảo mật; chưa phải quyền camera |
| navigator.mediaDevices | Browser | Kiểm tra API thiết bị tồn tại; chưa chứng minh có thiết bị vật lý |
| controller | new AbortController() của lần gọi này | Request identity riêng và công cụ hủy |
| controller.signal | Thuộc controller | Chuyển xuống fetch và đọc aborted |
| timeout | Mã timer window.setTimeout trả về | Dùng để clear timer; không phải duration |
| 15_000 | Hằng số ms | Timeout HTTP 15 giây |
| result | Await requestJoinCredentials | Credentials đã qua kiểm tra cơ bản |
| cause | Giá trị bị throw/reject | Chọn thông báo lỗi; không mặc định tin rằng luôn là Error |

**Bước A:** nếu pending hoặc joined thì return. Xóa error cũ. Nếu không secure context hoặc thiếu mediaDevices, setError và return mà chưa gọi backend.

**Bước B:** tạo controller, gán pending, set loading true, đặt timer. Dữ liệu controller là biến riêng của lần gọi, không bị đổi khi pending trỏ sang request khác.

```ts
const timeout = window.setTimeout(() => controller.abort(), 15_000);
```

**Chốt callback timer:** abort request này khi quá 15 giây. Nó không reset phiên mới, không dừng cuộc gọi và không phải token TTL.

**Bước C:** await API. Nếu signal chưa aborted, set joined=true rồi set credentials. Lưu ý joined bật trước khi SDK bắt đầu kết nối; tên này là latch chống phiên trùng.

**Bước D — catch:** chỉ xử lý khi `pending.current === controller`. Abort hiện hành được trình bày là timeout; TypeError là thông báo mạng; Error khác dùng message; giá trị lỗi khác dùng fallback. Cách trình bày TypeError là phân loại chung, không chẩn đoán chính xác mọi nguyên nhân network/parse.

**Bước E — finally:** luôn clear timer. Chỉ set pending=null/loading=false nếu request còn hiện hành.

### 11.6. Tại sao phải so controller ở catch và finally?

```text
Join A: pending = controllerA
Hủy: abort A, pending = null
Join B: pending = controllerB
A trả response/lỗi muộn:
  controllerA không phải pending hiện tại
  => A không được ghi lỗi hoặc tắt loading của B
```

Ngay cả fetch mock hoặc một bước xử lý sau fetch vẫn trả về muộn, kiểm tra signal ngăn lưu credentials của request đã bị hủy. Tín hiệu abort không phải giao dịch rollback ở backend.

**Chốt hàm join():** điều phối xin token có guard, timeout, hủy, kiểm tra request hiện hành và cập nhật state. Đây là bước bắt đầu phiên frontend, không phải hàm thực hiện media connection.

### 11.7. Object hook trả về

`return { credentials, isJoining, error, join, leave, endSession }` dùng shorthand. Ví dụ join tương đương join: join. MeetingPage đọc state và truyền actions xuống UI; không cần biết request/controller được quản lý bên trong.

**Chốt hàm useMeetingSession():** đóng gói dữ liệu và actions cho một phiên frontend. Nó là lớp điều phối session, độc lập với HTTP transport chi tiết và room/media state của LiveKit.

### Hàm requestJoinCredentials(signal)

**Ai gọi:** join trong hook. **Input:** AbortSignal. **Output:** `Promise<JoinCredentials>` hoặc reject Error.

| Tên/option | Giá trị / nguồn | Vai trò |
| --- | --- | --- |

| signal trong object | Shorthand signal: signal | Nối khả năng hủy từ hook xuống HTTP |

| data | unknown từ await response.json() | JSON chưa được tin cậy về cấu trúc |

```ts
const baseUrl = (import.meta.env.VITE_API_URL?.trim() || '')
  .replace(/\/$/, '');
```

Chuỗi trống ghép thành `/api/livekit/token`. URL có / cuối bị bỏ một dấu để tránh hai dấu / khi nối endpoint. Template literal dùng backtick và `${baseUrl}`.

HTTP 429 → Error tham gia quá nhiều; 503 → Error phòng chưa sẵn sàng; lỗi HTTP khác → Error cấp quyền chung. Throw chuyển điều khiển về catch của hook. Fetch network failure cũng reject; parse JSON sai có thể throw.

| Kiểm tra JSON | Lý do |
| --- | --- |
| !data và typeof object | Loại null/primitive trước khi dùng in/property |
| Có token, là string, không rỗng | Bắt buộc có chuỗi token, chưa verify chữ ký JWT |
| Có serverUrl, là string, bắt đầu wss:// | Tránh đưa protocol sai vào SDK; chưa validate toàn URL hoặc domain |
| roomName là string | Kiểm tra kiểu; code chưa bắt buộc chuỗi không rỗng |
| participantIdentity là string | Kiểm tra kiểu; code chưa xác thực UUID hoặc chuỗi không rỗng |

`as JoinCredentials` ở cuối là cam kết kiểu sau các if, không tự biến đổi/validate object. Không có localStorage/sessionStorage ở đây.

**Chốt hàm requestJoinCredentials():** thực hiện HTTP và kiểm tra hợp đồng response cơ bản, trả dữ liệu hoặc lỗi thân thiện cho hook. Đây là API client frontend, không quyết định quyền hay verify JWT.

| Injectable | Decorator đánh dấu service cho DI; không tự tạo HTTP route |
| ServiceUnavailableException | Exception Nest ánh xạ HTTP 503 |
| ConfigService | Đọc cấu hình backend đã chuẩn hóa |
| randomUUID | Node crypto tạo identity UUID mới mỗi request |
| AccessToken | LiveKit server SDK tạo/ký JWT |
| TrackSource | Enum nguồn media để giới hạn publish |
| JoinCredentials | Interface response phía backend; các trường tương ứng frontend types.ts |

### 15.2. Constructor(config)

`private readonly config: ConfigService` lưu instance cấu hình Nest cung cấp. Không nhận config từ browser và không đọc secret qua props frontend.

**Chốt constructor:** cấp cho service khả năng đọc cấu hình backend. Đây là dependency để biết URL, room, secret và chính sách PoC.

### 15.3. Hàm createJoinCredentials()

**Ai gọi:** controller hoặc trực tiếp trong backend tests. **Input:** không có tham số/body. **Output:** Promise chứa serverUrl, roomName, participantIdentity, token; thiếu cấu hình/PoC tắt trả lỗi 503.

| Biến | Nguồn / kiểu | Vai trò và nơi dùng |
| --- | --- | --- |
| serverUrl | Config LIVEKIT_URL | Trả cho frontend; không gọi server này trong hàm để kiểm chứng |
| apiKey | Config LIVEKIT_API_KEY, trim | Nhận diện bộ thông tin ký; truyền vào AccessToken |
| apiSecret | Config LIVEKIT_API_SECRET, trim | Ký JWT; không trả response, không đặt VITE_ và không log |
| participantIdentity | randomUUID(), string | Identity gắn vào token và trả metadata cho client; mỗi Join mới có mã mới |
| roomName | LIVEKIT_ROOM_NAME | Room cố định; dùng làm grant.room và metadata response |
| accessToken | new AccessToken(...) | Object xây token, chưa phải chuỗi JWT cuối cùng |
| token trong response | Await accessToken.toJwt() | Chuỗi JWT client dùng kết nối; không phải secret |

Kiểm tra `!POC_ENABLED || !serverUrl || !apiKey || !apiSecret`: một phần không đạt thì throw 503 trước khi tạo token. ?.trim() cho phép đọc thiếu key/secret mà không gây TypeError, rồi chủ động báo lỗi chung.

```ts
const accessToken = new AccessToken(apiKey, apiSecret, {
  identity: participantIdentity,
  ttl: this.config.getOrThrow<number>('LIVEKIT_TOKEN_TTL_SECONDS'),
});
```

| Tham số/option | Vai trò | Không được hiểu thành |
| --- | --- | --- |
| apiKey | Thông tin nhận diện issuer/bộ credential ký | Password user |
| apiSecret | Bí mật ký JWT | Dữ liệu có thể gửi browser |
| identity | Mã participant của JWT | User account cố định hoặc tên hiển thị đã đăng nhập |
| ttl | Thời hạn token, số hiện tại tính bằng giây | Thời lượng phòng họp hoặc timeout fetch |

Token là dữ liệu có chữ ký, không phải một chỗ để nhét secret vì giả định client không đọc được. Quyền được kiểm tra khi LiveKit chấp nhận kết nối. Token expiry không tự đặt timer ở UI để kết thúc một cuộc gọi đang diễn ra.

```ts
accessToken.addGrant({
  room: roomName,
  roomJoin: true,
  canPublish: true,
  canSubscribe: true,
  canPublishData: false,
  canPublishSources: [TrackSource.CAMERA, TrackSource.MICROPHONE],
});
```

| Grant | Giá trị | Cho phép/giới hạn |
| --- | --- | --- |
| room | roomName | Chỉ định room mà giấy phép này dùng để join |
| roomJoin | true | Cho phép tham gia room đó |
| canPublish | true | Cho phép gửi media, nhưng còn chịu giới hạn nguồn bên dưới |
| canSubscribe | true | Cho phép nhận media của participant khác |
| canPublishData | false | Không cấp quyền gửi data message bằng participant token này |
| canPublishSources | camera, microphone | Chỉ camera/mic, không cấp screen share; ẩn UI chỉ là lớp giao diện, grant mới là quyền |
| roomAdmin/roomCreate | Không cấp | Không cấp các quyền admin/create qua các trường đó; không phải một API tạo phòng động |

`return { serverUrl, roomName, participantIdentity, token: await ... }` dùng shorthand cho ba trường đầu, trường token có expression riêng. toJwt() là thao tác async ký JWT. Không có RoomServiceClient call, database insert hoặc kiểm tra user.

**Chốt hàm createJoinCredentials():** áp chính sách PoC do server quyết định, tạo identity và ký JWT giới hạn quyền vào room cố định. Đây là trung tâm cấp quyền Module 1, chưa phải authorization theo tài khoản hoặc kiểm chứng Cloud/media.

### 15.4. HTTP 200 chứng minh điều gì?

HTTP 200 chứng minh request tới backend và hàm tạo response ký token thành công. Nó chưa chứng minh API key/secret khớp project LiveKit thật, browser có quyền thiết bị, participant đã Connected hoặc remote nhận được media. Các bước đó nằm sau response.

**Chốt hàm handleConnectionError():** hiển thị lỗi kết nối/thiết bị chung trong phòng. Đây là xử lý thông báo, không phải thuật toán phục hồi kết nối.

## 17. Timeline đầy đủ: thành công, hủy, lỗi và Leave

### 17.1. Một lần Join thành công

| Bước | File/đối tượng | Thay đổi |
| --- | --- | --- |
| 1 | MeetingPage | Click gọi join |
| 2 | Session hook | pending=controller, loading=true |
| 3 | token-api | POST cùng origin /api/livekit/token |
| 4 | Vite proxy | Chuyển request tới Nest |
| 5 | ThrottlerGuard | Cho qua nếu chưa bị giới hạn |
| 6 | Controller/service | Tạo UUID, grant và JWT |
| 7 | token-api | Kiểm tra HTTP và JSON |
| 8 | Session hook | joined=true, credentials=result; finally loading=false |
| 9 | MeetingPage | Render lazy MeetingRoom |
| 10 | LiveKitRoom | Dùng token/serverUrl kết nối và xử lý thiết bị |
| 11 | RoomContent | Hiện trạng thái/participants/tracks; audio renderer phát remote audio |

Browser có thể đang tải room bundle/kết nối SDK sau khi isJoining đã false. Không dùng loading token để suy ra SDK connected.

### 17.2. Hủy trong lúc xin token

leave abort + xóa pending/credentials. Response cũ bị kiểm tra signal; catch/finally cũ không thay đổi request mới vì so controller. Backend có thể đã ký token, nhưng frontend không sử dụng token đó. Hủy fetch không tự thu hồi JWT đã ký.

### 17.3. Lỗi token API

429/503/HTTP khác → token-api throw → hook catch lưu lobby error → finally dọn pending/loading → người dùng có thể Join lại. Guard rate limit vẫn có thể chặn retry cho đến khi hết thời gian áp dụng.

### 17.4. Lỗi thiết bị hoặc kết nối SDK

onError/onMediaDeviceFailure đặt error trong phòng. Không phải mọi lỗi này tự xóa credentials. Khi SDK phát disconnected, onEnded mới dọn session. Người dùng còn nút Rời phòng riêng để reset và Join mới. Các handler hiện không phân loại lỗi sâu hoặc tự xóa thông báo sau khi thiết bị đã khôi phục.

### 17.5. Hai đường Leave

```text
Nút Rời phòng riêng:
onLeave → hook.leave → credentials=null → MeetingRoom unmount → SDK disconnect/cleanup

Leave trong ControlBar:
SDK disconnect → onDisconnected → handleDisconnected → endSession → lobby
```

State error lobby và error room độc lập. Callback chủ động rời không yêu cầu message lỗi. Cleanup SDK không cần một request Nest để xóa phòng database vì module chưa có database/room workflow.

### 20.2. Hàm Stop-OwnedProcess(record)

**Ai gọi:** nhánh -Stop hoặc finally. **Input:** record `{ id, started }`. **Output:** không trả dữ liệu nghiệp vụ; có thể dừng process.

| Expression/option | Vai trò |
| --- | --- |
| Get-Process -Id record.id | Tìm process hiện có |
| -ErrorAction SilentlyContinue | Process không tồn tại thì không tạo lỗi dừng cho bước tìm |
| StartTime.ToUniversalTime().ToString('o') | Chuẩn hóa thời gian UTC dạng round-trip để so với record |
| -eq record.started | Kiểm tra process hiện tại đúng process đã ghi, không chỉ trùng PID |
| Stop-Process -Id process.Id | Chỉ dừng sau khi kiểm tra khớp |

PID có thể được tái sử dụng. Đối chiếu start time giảm nguy cơ dừng nhầm. Record là runtime state cục bộ, không phải cơ chế xác thực chống người có quyền sửa máy.

**Chốt hàm Stop-OwnedProcess():** dừng đúng tiến trình đã ghi nhận trong phiên khi còn sống và khớp start time. Đây là cleanup ownership của script.

### 20.3. Nhánh Stop và guard chạy trùng

Nhánh Stop: nếu statePath tồn tại thì đọc file Raw → ConvertFrom-Json → foreach record → Stop-OwnedProcess. Nếu không có file thì báo không có session ghi nhận. `exit 0` kết thúc nhánh, không build/start.

Nhánh start: tạo runtimeDir nếu cần, đọc previous và kiểm tra từng PID/start time. Có process còn khớp thì throw yêu cầu dừng phiên cũ. State file cũ không tự chứng minh tunnel đang sống; phải kiểm tra tiến trình.

**Chốt nhánh Stop:** thực hiện yêu cầu dừng từ npm theo record. **Chốt guard start:** tránh dựng hai môi trường tunnel trùng cổng/tài nguyên từ cùng script.

### 20.5. Hàm Wait-Http(Url, Child)

**Ai gọi:** sau khi dùng/start backend và sau start preview. **Input:** URL HTTP và process object tùy trường hợp. **Output:** return khi status 200, throw khi process chết hoặc hết số lần thử.

## 21. Hai đường mạng khi dùng tunnel

```text
Browser -> HTTPS Cloudflare URL -> cloudflared -> preview 127.0.0.1:4173
                                                  |
                                                  +-- /api -> NestJS 127.0.0.1:3000

Browser <-------------------- audio/video --------------------> LiveKit Cloud
```

Browser thấy HTTPS, Cloudflare có kết nối tunnel tới máy chạy. Chặng HTTP cuối ở loopback cùng máy. Không cần các thiết bị cùng LAN và không tự mở inbound port router. Máy chủ vẫn phải bật và có Internet. Quick Tunnel URL thay đổi theo lần tạo, không phải domain cố định.

Link không có application login/Access được cấu hình trong script. Ai có link có thể xin token PoC nếu limiter cho phép. HTTPS bảo vệ đường truyền, không phân quyền người dùng. Rate limit qua loopback proxy có thể gộp nhóm test; đây là giới hạn request token, không phải giới hạn số người đang họp.

## 30. Các giới hạn cần nói đúng khi trình bày

1. Chưa có auth/authorization theo user. Token endpoint đang cấp quyền khách vào cùng room khi bật PoC; CORS, rate limit, UUID không thay authentication.
2. Health 200 chỉ là liveness; token 200 chỉ chứng minh ký response. SDK Connected cũng chưa chứng minh media hai chiều hoặc thiết bị đã được cấp quyền.
3. Người dùng đã xác nhận nghe/thấy giữa nhiều tab cùng máy. Chưa có bằng chứng nghiệm thu đầy đủ hai thiết bị/hai mạng, permission, reconnect, cleanup và capacity.
4. Token TTL không tự dừng cuộc gọi sau 300 giây. HTTP timeout 15 giây và rate limiter TTL 60 giây là hai cơ chế khác.
5. Identity mới mỗi Join, chưa có user account/tên hiển thị bền vững; token chỉ giữ trong memory của phiên frontend.
6. Error handling hiện là thông báo chung. Không có retry UI chuyên biệt hoặc ErrorBoundary riêng cho lỗi tải lazy bundle; lỗi thiết bị hiện chưa tự xóa message khi phục hồi.
7. Nhiều người qua proxy có thể chia sẻ rate-limit tracker IP. Limiter memory không đồng bộ nhiều instance; chưa có đo tải để công bố số người tối đa.
8. Quick Tunnel là link thử, URL đổi, máy chủ phải hoạt động, script không cấu hình Access/login. Preview không phải production server; không bật PoC cấp token khách trong production backend.
9. Hiding controls không phải phân quyền. Token grant mới giới hạn publish sources; không cấp data publishing nhưng điều đó không thay auth/privacy toàn ứng dụng.
10. Build/typecheck/tests không thay thử thiết bị thật. Kết quả checks cần nói rõ thời điểm/phạm vi, không suy ra mọi điều kiện mạng đều đạt.

| Type interface/as có kiểm tra JSON thật không? | Không. Các if runtime trong token-api mới thực hiện kiểm tra cơ bản |
