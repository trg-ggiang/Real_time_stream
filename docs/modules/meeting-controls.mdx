## Scope and setup

The NestJS API uses Supabase Auth access tokens (`Authorization: Bearer ...`) and verifies that the same UUID exists in `public.users.user_id`. The service role key stays in the backend. Apply `supabase/migrations/202611070001_meeting_controls.sql` before using meeting endpoints. Configure `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, and LiveKit credentials in `backend/.env`.

The migration adds `meetings.max_participants` and `meetings.allow_self_unmute`, plus an atomic seat reservation function. The provided schema did not contain these two settings. Capacity defaults to 20 for existing meetings; newly created meetings must specify their capacity.

## API

All routes below require a valid Supabase Auth bearer token. IDs are UUIDs; join uses the meeting code.

| Method and route | Purpose | Permission |
| --- | --- | --- |
| `POST /api/meetings` | Create a meeting. Body: `{ "title": "...", "maxParticipants": 20, "waitingRoomEnabled": true, "allowSelfUnmute": true }` | Authenticated user becomes owner |
| `POST /api/meetings/:code/join` | Request entry or receive LiveKit credentials when admitted | Authenticated member |
| `POST /api/meetings/:id/join-requests` | List waiting requests | Owner or moderator |
| `POST /api/meetings/:id/join-requests/:memberId/approve` | Admit a pending member | Owner |
| `PATCH /api/meetings/:id/members/:memberId/moderator` | Set `{ "enabled": true }` to grant or false to revoke moderator role | Owner |
| `POST /api/meetings/:id/members/:memberId/mute` | Mute the member's published microphone track in LiveKit | Owner or moderator |
| `POST /api/meetings/:id/members/:memberId/remove` | Remove a member and disconnect them from LiveKit | Owner |
| `PATCH /api/meetings/:id/settings` | Change `waitingRoomEnabled`, `maxParticipants`, and/or `allowSelfUnmute` | Owner |
| `POST /api/meetings/:id/leave` | Close the member's active attendance reservation | Authenticated member |

When waiting room is on, join returns `{ "status": "pending" }` without a media token. After approval, the client calls join again. When the capacity is reached, join returns HTTP 403 with `Meeting is full.` Seat reservation is serialized in Postgres to avoid overbooking concurrent requests.

When self-unmute is disabled, the moderator mute operation also removes that participant’s microphone publishing permission (camera remains allowed). When enabled, the microphone track is muted server-side and the participant may unmute themselves. Existing participants whose permission was revoked need a refreshed token/reconnect after the owner enables self-unmute again.

## Integration limits

The caller must leave through the API for the capacity reservation to be released. Abrupt disconnects can keep an attendance active until a LiveKit webhook or operational cleanup updates `left_at`; webhook cleanup is not part of this implementation. The existing `/api/livekit/token` endpoint remains the separate static-room PoC and does not grant access to meetings created here. Frontend integration and full authentication signup/login are not included.
